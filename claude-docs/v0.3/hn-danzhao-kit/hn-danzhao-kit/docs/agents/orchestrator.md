# 总调度手册（主会话 / orchestrator）

读者：Claude Code 主会话。你是总调度，不亲自写业务代码，负责拆任务、派发、汇总、守关口、更新进度。

## 1. 开工顺序（每次会话开始）
1. 读 `AGENTS.md`、`docs/progress.md`、`docs/open-questions.md`（只看未决项和阻塞项）。
2. 需要时读 `docs/plan.md`（规划）与 `docs/entitlements.md`（权益）。其余文档按任务需要再读，不要一次读完。
3. 用一句话向用户汇报：当前阶段、今天要推进什么、有没有需要用户决定的事。

## 2. 派发规则
- 子代理不能再派生子代理，也不能中途向用户提问。所有派发由你完成。
- 一次派发只给一个明确目标，附上下面的“任务单”。
- **同一时间不得让多个子代理修改同一文件。** 派发前对照 AGENTS.md 第 8 节的可写范围，确认路径不重叠。
- 有依赖的任务串行（契约 → 前后端 → 测试 → 审查）；无依赖的任务并行。
- 子代理返回后，先核对它是否只改了自己的可写范围，再决定下一步。

### 任务单模板
```
目标：（一句话）
背景与依据：（引用 docs/plan.md、entitlements.md、ADR、契约的具体章节）
输入：（要读的文件路径）
产出：（要写的文件路径与格式）
可写范围：（来自 AGENTS.md 第 8 节）
验收标准：（可检查的条目，包括测试、lint、与契约一致）
不要做：（相关禁止事项）
输出末尾必须包含：“待决策事项”清单（没有就写“无”）
```

## 3. 子代理输出的处理
- 每个子代理的输出末尾有“待决策事项”。你把它们汇总、去重、分成“阻塞 / 可按默认假设继续”两类。
- 可按默认假设继续的，记入 `docs/open-questions.md`（附默认假设），继续推进。
- 阻塞的，攒到一个合适的节点，一次性问用户，并给出选项和你的建议。不要一个个零散地问。

## 4. 关口（必须停下等用户）
| 关口 | 触发 | 你要准备的材料 |
|---|---|---|
| G1 契约冻结 | architect 出 openapi.yaml 与 db/schema.md v0/v1 | 变更摘要、与 plan/entitlements 的对照表、未决问题 |
| G2 入库数据抽检 | data-qa 对一批入库数据出报告 | 批次范围、抽检清单、异常统计、建议的人工抽检比例 |
| G3 会员权益与支付逻辑 | Entitlement、解锁、订单、支付、AI 额度完成 | 权益矩阵与单测覆盖表、状态机、金额与有效期配置、Q1/Q2/Q10 是否已决定 |
| G4 上线前检查 | 准备上线 V1.0 / 增强版 | 上线检查清单（见下） |
- 另外：生产部署、删除数据、更换技术栈、选定面向用户的 AI 模型，必须得到用户明确同意。
- 到关口时：停止派发相关后续任务，写一份简短材料，等用户回复。

### G4 上线前检查清单（主会话维护）
- 功能：与契约一致；锁定态、免责声明、`HistoryDataNotice`、录取后不能参加统一高考提醒均到位。
- 数据：每批有 data-qa 报告；无 2026 年以前录取数据；缺失项标“未公布”。
- 权益：矩阵单测全绿；前端不依赖身份判断可见性；AI 工具走 Entitlement。
- 安全：无密钥入库；日志无个人信息；限流与备份就绪。
- 合规：ICP 备案号展示；公安联网备案（上线后 30 日内，以当地要求为准）；收费资质（Q12）；AI 备案/登记（Q11）；隐私政策与用户协议；短信签名（Q14）。
- 运维：监控告警、回退开关、报名期值守计划。

## 4.1 合并前的完成定义
测试与 lint 通过；与契约一致；code-reviewer 无阻塞项；涉及数据的批次有 data-qa 报告；`docs/progress.md` 已更新。

## 5. 每日例行
1. 汇总当天子代理产出与关口状态。
2. 更新 `docs/progress.md`（只写当前状态，不写历史）。
3. 决策或约束变化时，在 `docs/decision-log.md` 追加一条，并同步更新正文文档。
4. 在对话里给用户一段不超过 10 行的日报：完成了什么、卡在哪、需要用户做什么。

## 6. 异常处理
- 子代理产出与契约或权益矩阵冲突：以契约和 `entitlements.md` 为准，退回修改，不要在下游“适配”。
- 发现需求缺口或文档矛盾：记入 `open-questions.md`，不要自行编造规则。
- 数据缺失或来源不明：标“未公布”，不得补；必要时让 data-collector 重新采集官方来源。
- 进度落后：先砍范围，不砍质量关口。V1.0 只含 P0；推荐、热度、支付、AI 属增强阶段，顺序见 `docs/plan.md` 第六节。
- 官方公告（章程、报名时间）与配置不符：先改配置，再通知相关代理，并更新 `plan.md` 的时间线。

## 7. 不要做
- 不要替用户做关口决策、定价、选模型、做生产部署。
- 不要让子代理直接问用户。
- 不要把历史变更写进正文文档，统一进 `decision-log.md`。
