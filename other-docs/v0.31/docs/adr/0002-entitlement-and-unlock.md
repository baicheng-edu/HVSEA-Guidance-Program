# ADR-0002 权益判定与单校解锁
状态：accepted（价格与细则待确认：Q1、Q2）　｜　日期：2026-11-10　｜　决策人：产品负责人

## 背景
权益原则为“历史免费，今年付费”。付费价值是 2027 实时报名数据及其衍生功能。商品有会员（全部学校）、单专业解锁（68 元）、整校解锁（288 元）。AI 对话也需要按权益提供数据。

## 决策
1. **唯一判定入口**：后端 Entitlement 服务的 `can_view(user, resource, scope)`。接口层、AI 工具层、导出层都调用它，前端和提示词都不参与判定。
2. **脱敏 + 锁定标记**：未解锁资源仍返回实体身份信息，敏感数值为 `null`，响应带统一 `access` 块（`locked`、`lock_reason`、`unlock_options`）。
3. **解锁是用户属性**：`UnlockGrant(user, school, scope=major|school, major?, expires_at)`，与会员并存；会员覆盖全部学校。
4. **价格与有效期放配置**：金额以分存储，订单保存价格快照；不抵扣规则用开关预留。
5. **阶段区分**：`stage_not_open`（数据尚未公布）与 `need_unlock_or_member`（需付费）分开，避免误导用户。
6. **支付可替换**：订单模型独立于支付渠道；V1.0 用兑换码与后台人工开通，微信支付（Native / JSAPI / 小程序）按终端后续接入。
7. **AI 额度**：Redis 计数，按 Asia/Shanghai 自然日重置，扣次要原子，失败不计次。

## 备选方案与取舍
- 前端按身份隐藏：可被绕过，且无法约束 AI，不选。
- 按“档位”建模（免费/单校/会员）：单校解锁可叠加在任意用户上，档位模型不够，改为“用户 + 会员 + 解锁列表”。

## 后果
- 契约必须定义 `access` 块与 `GET /me/entitlements`。
- 权益、解锁、额度、阶段必须有单测（见 `docs/entitlements.md` 第 7 节）。
- 权益与支付逻辑属于 G3 关口，需用户亲自把关。
