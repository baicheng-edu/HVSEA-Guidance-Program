# 权益、解锁与 AI 额度规则（Entitlements）

状态：已按产品负责人 2026-11-10 的确认定稿；标“待确认”的项见 `open-questions.md`，实现时先按“默认假设”做，并做成配置。
本文件是权益规则的唯一依据。接口契约、后端 Entitlement 服务、前端锁定态、AI 工具的行为都以此为准。

## 1. 设计原则
1. **历史免费，今年付费。** 不涉及 2027 招生季数据的功能全部免费，用来吸引用户注册使用。
2. **付费价值 = 2027 实时报名数据 + 基于它的判断。** 即报名人数、竞争度、趋势、预警，以及基于它的志愿推荐、方案和 AI 实时指导。
3. **教育用户。** 单招各校单独命题、单独组织考试，没有统一排名，录取难度取决于“报名人数 ÷ 招生计划数”。历史数据页面必须带 `HistoryDataNotice`，引导用户看今年报名情况并每日复核。
4. **后端统一判定。** 前端和 AI 都不自行判断可见性；未解锁内容返回脱敏数据 + `locked: true`。
5. **规则可配置。** 价格、有效期、额度、阶段窗口都放配置表，不硬编码。

## 2. 身份
| 身份 | 说明 |
|---|---|
| 游客 | 未登录。可浏览历史类内容（默认假设，Q8）；收藏、保存、方案、AI 需登录 |
| 免费用户 | 已注册登录，无会员、无有效解锁 |
| 单校解锁用户 | 免费用户 + 至少一个有效解锁（见第 4 节）；解锁是叠加在用户上的属性，不是独立档位 |
| 会员 | 已开通会员，权益覆盖全部学校 |

## 3. 功能权益矩阵

### 3.1 历史与基础（全部免费）
| 功能 | 游客 | 免费用户 | 会员 |
|---|---|---|---|
| 院校库、专业库、荣誉标签、王牌专业 | ✓ | ✓ | ✓ |
| 院校筛选（全部条件） | ✓ | ✓，可保存筛选 | ✓ |
| 院校 / 专业对比（最多 4 所，差异高亮） | ✓ | ✓ | ✓ |
| 去年（2026）招生计划，院校 × 专业明细 | ✓ | ✓ | ✓ |
| 去年（2026）录取情况明细 | ✓ | ✓ | ✓ |
| 2024–2026 简章原文与结构化要点 | ✓ | ✓ | ✓ |
| 资讯 | ✓ | ✓ | ✓ |
| 收藏、对比记录、考生档案 | 需登录 | ✓ | ✓ |
| 简章与公告提醒（站内 / 微信） | 需登录 | ✓，数量不限（默认，Q7） | ✓ |

说明：
- 录取数据只有 2026 年，不提供“多年趋势”。
- 对比表里如果含 2027 竞争度列，该列按第 3.2 节脱敏，其余列照常显示。
- 所有历史数据页面带 `HistoryDataNotice`。

### 3.2 2027 招生季数据
| 功能 | 游客 | 免费用户 | 单校解锁（范围内） | 会员 |
|---|---|---|---|---|
| 2027 简章 / 章程原文与要点、章程公布的计划数 | ✓（默认免费，Q6） | ✓ | ✓ | ✓ |
| 报名人数、竞争度、竞争等级、按日趋势、预警（院校 × 专业） | 锁定 | 锁定 | ✓ | ✓ 全部学校 |
| 全部学校的竞争度榜单 | 锁定 | 锁定 | 仅范围内学校的条目 | ✓ |
| 志愿推荐与方案 | 需登录 | 赠送 1 次体验，可保存（Q4） | 同免费，数据按解锁范围 | 不限次数、可保存、多方案、导出 |
| AI 对话 | 需登录 | 10 次/天，不含实时数据；填报阶段不提供实时志愿指导 | 见第 5 节（Q3） | 100 次/天，含实时数据 |

“锁定”的含义：接口仍返回该实体的身份信息（学校、专业、章程计划数），但报名人数、竞争度、等级、趋势为 `null`，并带 `locked: true`、`lock_reason`、`unlock_options`。前端据此渲染锁定态和解锁入口。

## 4. 单校解锁（非会员付费）
| 商品 | 价格 | 范围 |
|---|---|---|
| 单专业解锁 | 68 元 | 一所学校的一个专业 |
| 整校解锁 | 288 元 | 一所学校的全部专业 |
| 会员 | 待定（Q1） | 全部学校 |

- 解锁内容（默认假设，Q2）：范围内的 2027 报名人数、竞争度、等级、按日趋势、预警；不含其他学校的数据和全省榜单。
- 有效期（默认假设）：到本年度录取结束，与会员一致；日期放配置。
- 叠加规则（待确认，Q2）：先买单专业再买整校是否抵扣、多次解锁累计后升级会员是否抵扣。实现先按“不抵扣”，用配置开关预留。
- 金额以“分”为单位存储（6800 / 28800），价格表放配置，订单记录下单时的价格快照。
- 在微信支付接入前（商户号 12 月就绪），V1.0 用兑换码与后台人工开通；订单与权益模型从第一天就按支付流程设计。

## 5. AI 对话额度与数据范围
| 项 | 免费用户 | 付费用户 | 说明 |
|---|---|---|---|
| 每日次数 | 10 | 100 | 按自然日（Asia/Shanghai 0 点重置）；1 次 = 用户发出 1 条消息并得到回复；报错或被拦截不计次（默认，可调） |
| 2027 实时数据 | 不提供 | 仅提供其权益范围内的数据 | 会员：全部；单校解锁用户：已解锁范围 |
| 填报阶段（官方志愿填报窗口，参照 2 月 26 日–3 月 4 日，配置化）的 AI 实时志愿指导 | 不提供 | 提供 | 免费用户在该阶段是否还能问政策、院校介绍等非指导类问题见 Q5，默认可问 |
| 非填报阶段 | 可问院校、专业、政策、历史数据、怎么看单招竞争 | 同左，且含权益范围内的 2027 数据 | 历史数据问答要附带“参考有限”提示 |

- “付费用户”默认理解为：会员，或持有至少一个有效解锁的用户（Q3 待确认）。
- AI 的工具调用与页面接口共用同一个 Entitlement 服务。工具返回 `locked` 时，AI 只能说明“这部分需要解锁”，不得估算。
- 额度与阶段限制由后端判定并在响应里返回 `ai.remaining_today`、`ai.realtime_allowed`，提示词只负责措辞，不负责判定。

## 6. 志愿方案的保存与体验次数
- 免费用户“赠送 1 次”体验，体验结果允许保存（默认理解：1 次 = 1 次完整的推荐生成并保存 1 个方案，第一志愿 + 第二志愿；Q4 待确认）。
- 免费体验生成的方案基于历史数据和考生画像，显示“仅依据历史数据，不含今年报名竞争度”，2027 竞争度相关理由按锁定态展示（默认，Q4）。
- 会员：不限次数，多方案，可导出。
- 方案页永久带：“仅供参考，以官方发布为准”“被高职单招录取后，不能再参加本年度统一高考和对口招生考试”“请在每日报名人数公布后复核”。

## 7. Entitlement 服务接口约定（给 architect 写契约用）
- `GET /me/entitlements`：返回身份、会员有效期、解锁列表（school_id、scope=major|school、major_id?、expires_at）、AI 额度（daily_quota、used_today、realtime_allowed）、方案体验（free_trial_remaining、can_save）。
- 所有受控资源的响应带统一的 `access` 块：`{ locked: boolean, lock_reason?: "need_login" | "need_unlock_or_member" | "stage_not_open", unlock_options?: [...] }`。
- 阶段未开放（例如 2 月 27 日之前没有报名数据）用 `stage_not_open`，与付费锁定区分。
- 权益判定函数 `can_view(user, resource, scope)` 是唯一入口；接口层、AI 工具层、导出层都必须调用它。
- 判定相关单测必须覆盖：游客 / 免费 / 单专业解锁 / 整校解锁 / 会员 / 会员过期 / 解锁过期 / 阶段未开放 / AI 额度跨日 / 并发扣次。

## 8. 用户教育的落点（产品要求）
| 位置 | 做法 |
|---|---|
| 去年计划、去年录取、历年简章页 | 页顶 `HistoryDataNotice`：各校单独命题、无统一排名，去年数据只能辅助，要看今年报名情况 |
| 首页 | 阶段横幅 + “单招怎么看竞争”科普入口（含“举例”标注的 A/B 校例子） |
| 院校详情 | 历史数据区与“今年报名”区并列，今年区未解锁时显示锁定态和一句话说明价值 |
| 志愿方案页 | 提醒每日报名人数公布后复核并调整 |
| 订阅 | 报名期提供“每日数据更新”提醒 |
| AI 助手 | 回答历史问题时附带参考有限提示；用户问“去年多少分能上”时，先解释单招没有统一分数线，再引导看今年报名 |

文案要求：不说“一定能/一定不能录取”；用“录取机会较大/极低”；举例必须标注“举例，非真实数据”。
